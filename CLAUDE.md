# CLAUDE.md — KorTrainer

Korean self-study trainer (Russian UI) following a fixed plan towards TOPIK in spring 2027.
Personal tool and a C# portfolio project: clean architecture, tests and an English README matter.

## Stack

.NET 10 (LTS) · ASP.NET Core Minimal API · EF Core 10 + SQLite · Blazor WebAssembly (hosted by the API)
· xUnit v3 on Microsoft.Testing.Platform · AwesomeAssertions · Docker/Podman.

The SDK may be installed per-user: `export PATH=$HOME/.dotnet:$PATH`.

## Commands

```bash
dotnet build                                   # TreatWarningsAsErrors is on for every project
dotnet test                                    # all tests; MTP runner is configured in global.json
dotnet test --project tests/KorTrainer.Domain.Tests
dotnet test -- --coverage --coverage-output-format cobertura
dotnet run --project src/KorTrainer.Api        # API + client on http://localhost:5116
dotnet tool restore && dotnet ef migrations add <Name> -p src/KorTrainer.Infrastructure -s src/KorTrainer.Api -o Persistence/Migrations
docker compose up --build                      # http://localhost:8080, data in volume kortrainer-data
```

Static web assets are only served from `dotnet run` in the Development environment or after publish.

## Layout and dependency rule

`Domain` (no dependencies) ← `Contracts` ← `Application` ← `Infrastructure` ← `Api`. `UI` (all pages) and
`Web` reference `Contracts` and `Domain` only; `Embedded` (UI + Infrastructure) and `Mobile` (Android) run the
back end in-process. Never reference EF or ASP.NET from Domain.

- Domain: `Hangul/` (Syllable, Batchim, Pronunciation, Romanizer, JamoCatalog, AnswerChecker, SentenceComparer),
  `Vocabulary/` (WordIndex, Hanja, HardWords), `Typing/` (Dubeolsik, HangulComposer, TypingLessons), `Grammar/`, `Numbers/`, `Srs/`, `Plan/`
  (Roadmap of self-paced steps, PlanContent with Russian lesson texts, StudyRhythm, Forecast), `Exercises/` (generators), `Entities/`.
- Application: one service per feature; validation via `Validator` → `ValidationFailedException` (400),
  `NotFoundException` (404). Time comes from `StudyClock` (wraps `TimeProvider`, uses the learner's time zone).
- Infrastructure: `AppDbContext` implements `IAppDbContext`; decks embedded from `Seed/words.json`
  (curated, loaded first) and `Seed/words-nikl.json` (generated — never edit by hand; rebuild with
  `dotnet run tools/deck/BuildNiklDeck.cs` from `tools/deck/*.tsv`).
- Content (`Infrastructure/Content`, embedded from `Seed/`): `hanja-glosses.tsv`, `sentences-tatoeba.json`
  (generated by `dotnet run tools/sentences/BuildSentences.cs`; never edit by hand), `texts.json` and
  `topik-reading.json` (authored, original — never copy real exam items). `tools/content/CheckContent.cs` lists
  text words the deck cannot link. Deck entries may carry hanja as a 5th field: `[korean, russian, pos, irr, hanja]`.
- Audio: `Infrastructure/Audio` serves Lingua Libre recordings listed in `Seed/audio-lingualibre.json`
  (generated by `dotnet run tools/audio/BuildAudioManifest.cs`), downloading on demand into
  `Audio:CacheDirectory`; tests must never reach Wikimedia (fake HTTP handler, `Audio:Prefetch=false`).
  They play only when the `NativeRecordings` setting is on (off by default: one MeloTTS voice for everything,
  `AppState.SpeakAsync` → synthesized → device TTS).
- UI (Razor class library): pages in `Pages/`, shared drill UI in `Components/ChoiceDrill.razor`, keyboard via
  `KeyboardComponentBase`, browser glue in `wwwroot/js/app.js` (served as `_content/KorTrainer.UI/...`).
  Pages talk to `IKorTrainerApi` (web: `HttpKorTrainerApi`; app: `LocalKorTrainerApi`, one DI scope per call),
  speech through `ISpeechOutput`, backups through `IBackupExporter`. A new endpoint needs both implementations.
- Mobile: `src/KorTrainer.Mobile` (net10.0-android, not in the slnx). Build with `tools/android/build-apk.sh`;
  the signing key is in `~/.config/kortrainer/` and must never be committed or regenerated (updates need it).

## Conventions

- Code, identifiers and comments in English; all user-facing text in Russian.
- Romanization is hidden unless `ShowRomanization` is on — never show Latin by default.
- Hangul logic uses Unicode arithmetic (`0xAC00`, `% 28`, `/ 588`), never tables of syllables.
- Domain logic is pure and deterministic: inject `Random`/`TimeProvider`, prefer immutable records.
- Activity entities store `LocalDate` (learner's day) at write time; group statistics by it.
- The plan is self-paced: `Roadmap` lists steps (keys `lesson-N`, `level1-N`, `level2-N`, `mock-exam`, `topik-N`,
  `maintenance` — stored in user data, never rename them). `PlanCursor` keeps exactly one open `PlanStepProgress`;
  `StepEvaluator` counts activity inside a step's UTC window. Never move the learner forward by date, and keep
  reminders gentle (no streak or "falling behind" wording).
- Write tests first for domain rules; keep Application tests on a migrated in-memory SQLite DB
  (`TestDatabase`), API tests via `KorTrainerApiFactory`.
- Exercise type ids live in `ExerciseTypes`; plan tasks reference them for automatic progress.
- Deck format: `[korean, russian, pos, irregularity?]`. `DeckKey` = `korean#n` (n-th occurrence), so
  append new homonyms after existing ones; translations can be edited in place.
- Commits: Conventional Commits (`feat:`, `fix:`, `test:`, `docs:`…).

   `TaskMetric.Read` + `StudyMaterials` and are marked by the page (`MarkReadAsync`, `/lesson/{day}`, Hangul guide);

   served by `SentenceService` as words); level 1 alternates words and phrases; level 2 and TOPIK repeat phrases aloud.
   Timed reading can be read aloud and checked by the recognizer (the learner still grades).

The deck has ~5,900 words (curated + NIKL A/B/C). Next ideas: offline answer queue, phone↔laptop sync, review of
